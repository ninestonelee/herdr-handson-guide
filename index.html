0-1. Herdr를 한 문장으로

Herdr(허더)는 AI 비서 여러 명을 한 화면에 앉혀 두고, 누가 일하는 중이고 누가 내 대답을 기다리는지 한눈에 보여 주는 "AI 비서실 관리판"이에요.

이름은 영어 herd(가축 무리)를 모는 사람(herder)에서 왔어요. 양 떼를 모는 목동처럼, 여러 AI 에이전트를 한곳에서 몰아요.

비유로 보면 이래요.

일상 비유 Herdr에서는
사무실 건물 세션: 따로 열고 다시 들어갈 수 있는 작업실 하나. 보통은 기본 세션 하나면 충분하고, 컴퓨터가 켜져 있는 한 계속 열려 있어요
층(부서) 작업공간(space): 프로젝트 하나. 예: "블로그", "회사 보고서"
회의실 탭: 프로젝트 안의 작업 단위. 예: "리서치", "초안"
회의실 안 책상 칸(pane, 페인): 터미널 하나. 여기에 AI 비서가 한 명씩 앉아요
비서 상태판 agents 목록: 누가 일하는지(◐), 끝났는지(✓), 나를 기다리는지(×)

그림의 '스페이스'는 이 책의 작업공간, '페인'은 칸과 같은 말이에요. 화면의 버튼 이름(spaces, pane)은 영어 그대로 적었어요.

0-2. 왜 필요할까요?

Claude Code 하나만 쓸 때는 터미널 창 하나면 충분해요. 그런데 Codex를 같이 쓰고, Claude를 두세 개 더 띄우면 어느새 창이 6~8개가 돼요. 진짜 문제는 창 개수가 아니라 이거예요.

  • 어느 AI가 아직 일하는 중인지 모른다
  • 어느 AI가 "이거 실행해도 돼요?" 하고 내 승인을 기다리며 멈춰 있는지 모른다 (몇십 분째 멈춰 있는 경우가 흔해요)
  • 실수로 창을 닫으면 하던 일이 날아간다

Herdr는 이 세 가지를 해결해요. ① 한 화면 정리 ② 상태 표시와 알림 ③ 창을 닫아도 뒤에서 계속 일하기.

💡 팁: AI를 하나만 쓴다면 굳이 Herdr가 필요 없어요. AI를 2~3개 이상 같이 돌리기 시작할 때 효과가 확 느껴져요. (출처: 영상 김플립·윤자동)

0-4. 터미널 생존 키트 (5분)

터미널은 글자로 컴퓨터에게 일을 시키는 창이에요. 마우스로 아이콘을 누르는 대신, 명령을 쳐서 Enter를 눌러요. 딱 이것만 알면 이 책을 따라올 수 있어요.

단계 1. 터미널 앱 열기

  • 맥: ⌘ + Space(스포트라이트) → "터미널" 입력 → Enter
  • 윈도우: 시작 버튼 → "Windows Terminal" 또는 "PowerShell" 검색 → 실행

💡 팁: 맥 기본 터미널로도 충분해요. 조금 더 빠르고 깔끔한 터미널을 원하면 영상 진행자들이 공통으로 추천한 Ghostty(ghostty.org, 무료)를 써 보세요. 이 맥에는 이미 Ghostty가 설치돼 있어요.

단계 2. 프롬프트 읽기

터미널을 열면 맨 앞에 herdr-연습 % 같은 글자와 깜박이는 커서가 보여요. 이걸 프롬프트라고 해요. "지금 이 폴더에 있어요, 명령을 입력하세요"라는 뜻이에요. 맥은 보통 %, 윈도우는 >로 끝나요.

단계 3. 기초 명령 5개 써 보기

한 줄씩 입력하고 Enter를 눌러 보세요. 순서는 이래요.

  1. pwd로 지금 위치를 봐요.
  2. ls로 이 폴더 안의 목록을 봐요.
  3. mkdir 블로그연습으로 새 폴더를 만들어요.
  4. cd 블로그연습으로 들어가요. 프롬프트가 블로그연습 %로 바뀌어요.
  5. cd ..로 다시 나와요.
명령 뜻 기억법
pwd 지금 있는 폴더 위치 보기 print working directory
ls 이 폴더 안의 목록 보기 list
mkdir 폴더이름 새 폴더 만들기 make directory
cd 폴더이름 그 폴더로 들어가기 change directory
cd .. 한 단계 위 폴더로 나가기 점 두 개 = 위층

단계 4. 멈추고 싶을 땐 Ctrl + C

명령이 끝나지 않고 계속 돌거나 뭔가 잘못된 것 같으면 Ctrl + C를 누르세요. ^C가 찍히고 바로 멈춰요.

⚠️ 주의: 터미널에서 Ctrl + C는 복사가 아니라 "그만!"이에요. 맥에서 복사는 ⌘ + C, 붙여넣기는 ⌘ + V예요. (Herdr 안에서는 마우스로 드래그만 해도 복사돼요. 2부에서 배워요.)

단계 5. 손 덜 쓰는 요령 2가지

  • ↑ 화살표: 방금 쓴 명령을 다시 불러와요. 같은 명령을 또 칠 필요가 없어요.
  • Tab 키: 폴더·파일 이름을 몇 글자만 치고 Tab을 누르면 나머지를 채워 줘요. 오타가 줄어요.

✅ 확인하기: 터미널을 열고 pwd를 쳤을 때 /Users/내이름 같은 줄이 나오면 준비 완료예요.

(~는 내 홈 폴더라는 뜻이에요. 프롬프트가 herdr-연습 %로 바뀌면 잘 들어온 거예요.)

단계 2. herdr 실행하기

⚠️ 주의 (이미 herdr로 실제 일을 하고 있다면 필독): 그냥 herdr를 치면 어느 폴더에서든 지금 쓰고 있는 기본 작업실(기본 세션)에 붙어요. 그러면 연습하다가 실제 작업을 닫거나 끌 수 있어요. 이럴 때는 연습용 작업실을 따로 여세요.

practice라는 이름의 연습 세션이 새로 열려요. 이 책의 실제 화면도 이렇게 따로 만든 연습 세션에서 찍었어요. 이 경우 이 책에서 herdr라고 하는 곳은 모두 herdr --session practice로 바꿔 입력하세요. herdr를 처음 쓰는 분은 그냥 herdr로 해도 돼요.

단계 4. 에이전트 통합(integration) 설치하기

다음 화면은 설정(settings) 창의 integrations 탭이에요. 통합은 "AI와 herdr 사이의 전달선"이에요. 설치해 두면 herdr를 완전히 껐다 켰을 때 AI와 하던 대화를 다시 찾아 열도록 도와줘요(지원되는 AI이고 복원 설정이 켜져 있을 때). 일부 AI는 상태도 직접 알려 주지만, Claude와 Codex는 통합이 있어도 화면 글자를 보고 상태를 판단해요.

하는 법:

  1. ↑ ↓ 화살표로 claude에 맞추고 Enter(install) → 설치 표시가 생겨요
  2. Codex도 쓰면 codex에 맞추고 Enter
  3. 처음 설치하는 분은 available(설치 가능)로 보이고, 이미 깐 적이 있으면 update available로 보여요. 둘 다 Enter면 돼요
  4. not found는 herdr가 그 AI 프로그램을 찾지 못했다는 뜻이에요. 안 쓰는 AI면 무시하고, 쓰는 AI인데 not found면 일반 터미널에서 그 명령(예: claude)이 실행되는지 먼저 확인해요

⚠️ 주의: 통합을 설치하면 Claude·Codex 설정 폴더(예: ~/.claude)에 herdr용 작은 연결 파일이 추가돼요. 지우고 싶으면 나중에 herdr integration uninstall claude로 뺄 수 있어요.

초급 7장. 일 시키고 상태 읽기

이 장이 herdr의 핵심이에요. 왼쪽 표시만 보고 누가 뭘 하는지 아는 연습을 해요.

단계 1. Claude에게 말 걸기

왼쪽 Claude 칸의 입력창에 할 말을 쓰고 Enter.

단계 2. ◐ 작업 중 보기

AI가 답을 만드는 동안 agents 목록과 작업공간 이름 앞 표시가 ◐로 바뀌어요. 짧은 질문은 1~2초 만에 끝나서 놓칠 수 있어요. 아래 그림은 오른쪽 Codex에게 조금 오래 걸리는 일을 시켜서 찍은 예예요. 칸 안에도 Working(작업 중)이 보여요.

단계 3. × 막힘: 내 승인이 필요해요

AI가 "이 명령 실행해도 돼요?" 하고 물으면 표시가 ×로 바뀌어요. 이때 AI는 내가 답할 때까지 멈춰서 기다려요.

여러분 화면에서는 이런 승인창이 안 떠도 정상이에요. 그림을 똑같이 만들려고 원격 도구를 연결하거나 자동 허용 모드를 켜지 마세요. 승인창에서는 보통 첫 번째(허락)가 골라져 있어서, 생각 없이 Enter를 누르면 허락돼요. 취소하려면 Esc를 누르세요.

⚠️ 주의: × 표시를 보면 그 칸으로 가서 무엇을 하려는지 끝까지 읽고 허락할지 정하세요. 모르는 명령이면 취소(Cancel, No, Esc)가 안전해요. herdr의 가장 큰 가치는 "멈춰 있는 줄 몰랐던 AI"를 바로 찾아 주는 거예요.

단계 4. ✓ 완료와 알림

이번에는 Claude에게 시간이 좀 걸리는 일을 시키고, 바로 다른 탭(1)을 클릭해 보세요. 예를 들면 이렇게 말해요.

지금 연습 폴더 안에만 연습노트.md 파일을 만들고, 터미널 초보자를 위한 팁 5가지를 짧게 적어줘. 같은 이름의 파일이 있으면 덮어쓰지 말고 알려 주고, 다른 폴더에는 아무것도 쓰지 마.

(연습 폴더는 파일 접근을 막아 주는 보안 장치가 아니에요. 그래서 어디에 쓸지 말로 분명히 정해 주는 거예요.) 잠시 뒤 Claude가 일을 끝내면:

  • agents 목록과 작업공간 이름 앞에 ✓
  • 오른쪽 아래에 "claude finished" 팝업 (2장에서 inside herdr를 고른 경우)
  • 소리 (sound가 on일 때)

단계 5. 목록을 클릭해서 바로 이동하기

agents 목록의 claude를 클릭하면 그 AI가 있는 탭·칸으로 바로 이동해요. 내가 확인했으니 ✓는 ○(대기)로 바뀌어요.

💡 팁: 알림이 왔을 때 Ctrl + B → o를 누르면 알림이 온 AI로 바로 가요.

⚠️ 주의: 상태 표시는 100% 정확하지는 않아요. herdr는 화면에 보이는 글자로 상태를 짐작하는데, 처음 보는 질문 화면은 ○(대기)로 잘못 보일 수 있어요. 오래 조용하면 한 번 들어가 보세요. (출처: 공식 문서, 영상 윤자동)

✅ 확인하기: ◐, ×, ✓, ○ 네 가지를 각각 한 번씩 봤나요? 봤다면 초급의 가장 중요한 고비를 넘었어요.

중급 1장. 키보드 단축키: Ctrl + B 하나만 기억하기

herdr의 단축키는 같은 규칙이에요. Ctrl + B를 누르고 손을 다 뗀 다음, 글자 하나. 이 Ctrl + B를 "프리픽스(준비 키)"라고 불러요. (단, 목록이나 검색창이 열린 뒤에는 Ctrl + B 없이 화면에 적힌 키만 눌러요.)

단계 1. 프리픽스 모드 확인하기

Ctrl + B를 누르면 맨 아래 줄이 PREFIX로 바뀌어요. "다음 글자를 기다리는 중"이라는 뜻이에요.

⚠️ 주의 (한국어 사용자 필독): 키보드가 한글 입력 상태면 Ctrl + B 다음 글자가 안 먹을 수 있어요. 영어 입력으로 바꾸고 누르세요. 맥과 윈도우에서는 5장의 실험용 설정 한 줄(switch_ascii_input_source_in_prefix = true)로 자동 전환을 써 볼 수 있어요(최선을 다해 동작하는 옵션이라 안 될 때도 있어요). 0.9.5에서 이 문제가 많이 고쳐졌다고 해요. (출처: 기본 설정 파일 주석, 영상 윤자동)

단계 2. 단축키 목록 열고 검색하기

단축키는 외울 필요가 없어요. Ctrl + B → ?를 누르면 목록이 뜨고, /를 누른 뒤 단어를 치면 검색돼요(예: split, close, zoom).

💡 팁: 영어권 강의들의 공통 조언도 같아요. "외우지 말고 Ctrl + B → ? → /로 그때그때 찾아라." (출처: 영상 lustoykov)

단계 3. 키보드로 칸 나누기

  • Ctrl + B → v: 오른쪽으로 나누기
  • Ctrl + B → -(빼기): 아래로 나누기

칸을 옮겨 다닐 때는 클릭하거나, Ctrl + B를 눌렀다 떼고 h(왼쪽) j(아래) k(위) l(오른쪽) 중 하나를 눌러요.

단계 4. 한 칸만 크게 보기 (Zoom)

AI의 답이 길어서 칸이 좁게 느껴지면 Ctrl + B → z. 옆 칸이 잠시 사라지고 지금 칸이 화면 전체로 넓어져요. 다시 누르면 원래대로 돌아와요. 탭 이름 옆에 작은 Z가 붙는 것도 확대 중이라는 표시예요.

단계 5. 작업공간 사이를 키보드로 이동하기

Ctrl + B → w를 누르면 맨 아래가 NAVIGATE로 바뀌어요. 이 모드에서는 ↑ ↓가 작업공간을 고르는 키예요. 고른 뒤 Enter.

중급 4장. 통합 점검과 업데이트

통합(integration)이 낡으면 상태 표시가 덜 정확하거나, 껐다 켰을 때 대화가 안 이어질 수 있어요. 가끔 점검하세요.

단계 1. 통합 상태 보기

AI 대화창이 아니라 명령을 기다리는 칸(%, $, >로 끝나는 줄)에서 입력해요. AI가 떠 있는 칸에 치면 AI에게 말을 거는 게 되니까, 탭 줄의 +로 명령연습 같은 새 탭을 하나 만들어 거기서 입력하세요.

herdr integration status
표시 뜻 할 일
installed 최신이에요 없음
outdated (v7 < v11) 설치됐지만 옛 버전 업데이트
not installed 설치 안 됨 그 AI를 쓰면 설치, 안 쓰면 무시

단계 2. 통합 업데이트(또는 설치)하기

herdr integration install claude
herdr integration install codex

쓰는 AI만 하면 돼요(예: hermes, opencode). 설치 후 그 AI를 한 번 껐다 켜면 적용돼요. 설정 창(Ctrl + B → s)의 integrations 탭에서 Enter로 해도 같아요.

⚠️ 주의: herdr 자체 업데이트(herdr update)는 다른 얘기예요. 서버가 다시 시작되면서 돌고 있던 AI들이 끊길 수 있어요. 작업을 정리한 뒤 herdr 밖의 일반 터미널에서 하세요. 자세한 건 고급 7장에 있어요.

중급 5장. 설정 파일 고치기 (config.toml)

설정 창에 없는 것까지 바꾸려면 설정 파일을 고쳐요. 글자 몇 줄만 붙여 넣으면 돼요.

단계 1. 설정 파일 열기

설정 파일 위치는 ~/.config/herdr/config.toml이에요. 윈도우는 %APPDATA%\herdr\config.toml이고, 파일 탐색기 주소창에 %APPDATA%\herdr를 넣고 config.toml을 메모장으로 열면 돼요(새로 저장할 때 이름 뒤에 .txt가 붙지 않았는지 확인). 아래 open -e, mkdir, touch는 맥·리눅스용이에요.

  • Finder로 열기: Finder에서 ⌘ + Shift + G → ~/.config/herdr/ 입력 → config.toml을 텍스트 편집기로 열기
  • 터미널로 열기: 아래를 입력하면 맥 텍스트 편집기로 열려요
open -e ~/.config/herdr/config.toml

⚠️ 주의: "파일이 없다"는 오류가 나면 아래 두 줄로 빈 파일을 먼저 만들고 다시 여세요. 설정 파일이 비어 있어도 herdr는 기본값으로 잘 돌아가요.

mkdir -p ~/.config/herdr
touch ~/.config/herdr/config.toml

인터넷의 herdr --default-config > ... 같은 예시는 기존 파일을 덮어써요. 파일이 이미 있으면 그 명령은 쓰지 마세요.

단계 2. 추천 설정 붙여 넣기

비개발자에게 가장 쓸모 있는 설정이에요. 붙이기 전에 설정 파일을 복사해 백업해 두세요(Finder에서 파일 선택 → ⌘ + D로 복제).

  • 빈 파일이라면 아래 전체를 그대로 붙여 넣어요.
  • 이미 내용이 있다면 [ui], [ui.toast], [experimental] 제목이 파일에 있는지 먼저 찾아보세요. 있으면 제목은 빼고, 그 제목 아래에 없는 줄만 추가해요. 같은 이름의 설정이 이미 있으면 값만 바꿔요.
[ui]
# 상태를 기호(× ◐ ✓ ○)로 보기
status_indicators = "symbols"
# 나를 기다리는 AI가 목록 맨 위로
agent_panel_sort = "priority"

[ui.toast]
# 다른 곳을 보고 있을 때 herdr 화면 안에 알림 띄우기
delivery = "herdr"

[experimental]
# Ctrl+B 누를 때 자동으로 영어 자판으로 바꾸기 (한글 입력 문제 해결)
switch_ascii_input_source_in_prefix = true
# 한글 조합창이 입력 위치를 따라오게 하기 (Claude·Codex 입력창)
reveal_hidden_cursor_for_cjk_ime = true

⚠️ 주의: [ui]처럼 대괄호 제목은 파일 안에 한 번만 있어야 해요. 같은 제목이 두 번 있으면 설정이 적용되지 않아요. #으로 시작하는 줄은 설명(주석)이라 지워도 돼요. [experimental] 두 줄은 맥·윈도우용 실험 옵션이에요.

단계 3. 설정이 맞는지 검사하고 적용하기

저장한 다음 터미널에서 먼저 검사해요.

herdr config check

config: ok가 나왔을 때만 적용 명령을 입력해요. 오류가 나오면 백업해 둔 파일과 비교해서 고쳐요.

herdr server reload-config

이 명령은 AI를 끄지 않고 바로 적용해요. (herdr 화면에서 Ctrl + B → Shift + R 또는 menu → reload config도 같아요.)

그 밖에 바꿀 만한 설정

설정 (어느 제목 아래) 예시 효과
[ui.sound] 아래 enabled false 소리 끄기 (AI가 많으면 시끄러워요)
[theme] 아래 name "tokyo-night" 색 테마
[ui] 아래 sidebar_width 30 사이드바 너비 (기본 26)
[ui] 아래 tab_bar_position "bottom" 탭 줄을 아래로
[ui] 아래 mouse_scroll_lines 5 휠 한 번에 스크롤할 줄 수 (기본 3)
[ui.toast] 아래 delivery "system" 맥 알림 센터로 알림 받기

(출처: herdr 0.9.5 기본 설정 파일 주석, 공식 문서 configuration)

중급 6장. 플러그인으로 기능 더하기

플러그인은 다른 사람들이 만든 추가 기능이에요. 예를 들어 herdr-file-viewer를 깔면 herdr 안에서 폴더의 문서를 예쁘게 볼 수 있어요.

단계 1. 마켓에서 고르기

herdr.dev/plugins에 들어가면 플러그인 목록이 있어요. 인기순(Popular)으로 정렬해 많이 쓰는 것부터 보세요. 단, 별 개수는 안전하다는 인증이 아니에요. 설치 전에 아래 단계 2의 '설치 전에 AI에게 먼저 검사시키기'부터 해 보세요.

⚠️ 주의: 마켓 화면에도 쓰여 있듯이 목록의 플러그인은 herdr 팀이 검사하지 않아요. 플러그인은 내 컴퓨터에서 내 권한으로 프로그램을 실행해요. 별이 많고, 최근까지 업데이트되고, 설명이 분명한 것만 고르세요.

단계 2. 설치 명령 입력하고 미리보기 읽기

herdr plugin install smarzban/herdr-file-viewer

🗣️ 이렇게 말해 보세요 (설치 전에 AI에게 먼저 검사시키기)

herdr 플러그인 smarzban/herdr-file-viewer 를 설치하려고 해. 설치하기 전에 GitHub 저장소의 herdr-plugin.toml과 설치·빌드 스크립트를 읽고, 내 컴퓨터에서 무엇을 실행하는지, 인터넷으로 무엇을 보내는지 쉬운 말로 요약해 줘. 설치는 내가 직접 할게.

설치 명령을 넣으면 미리보기가 나오고 Install this plugin? [y/N]라고 물어요. 미리보기에서 저장소 이름, 빌드 명령, 자동 실행 항목을 확인하세요. 미리보기는 실행할 명령을 보여 줄 뿐 안전을 보증하지 않아요. 이해되지 않는 게 있으면 y를 누르지 말고 Enter(취소).

단계 3. 단축키 연결하기

플러그인 안내문(README)에 있는 [[keys.command]] 묶음을 설정 파일 맨 아래에 붙여 넣어요. file-viewer는 이렇게 생겼어요.

[[keys.command]]
key = "prefix+f"
type = "plugin_action"
command = "herdr-file-viewer.open-file-viewer"
description = "open file viewer in split"

단계 4. 검사하고 적용하기

herdr config check
herdr server reload-config

단계 5. 써 보기

Ctrl + B → f를 누르면 옆에 파일 뷰어가 열려요. 마크다운 문서가 제목·목록 모양 그대로 보여요.

💡 팁: 플러그인 관리 명령: herdr plugin list(설치 목록), herdr plugin update(업데이트), herdr plugin uninstall 이름(삭제), herdr plugin disable 이름(잠시 끄기).

중급 7장. AI에게 herdr를 조작시키기 (herdr 스킬)

여기서부터가 herdr가 그냥 화면 나누기 도구가 아닌 이유예요. 스킬(skill)은 AI에게 주는 "herdr 사용 설명서"예요. 스킬을 깐 AI는 말 한마디로 칸을 열고, 다른 AI를 띄우고, 결과를 읽어 와요.

단계 1. 스킬 설치하기

npx skills add herdrdev/herdr --skill herdr -g

(-g는 지금 프로젝트에만 두지 않고 내 사용자 계정 전체에 설치한다는 뜻이에요. 설치 화면에서 어느 AI에 적용할지 확인하세요. Node.js가 필요해요. 어렵다면 Claude에게 "이 명령으로 herdr 스킬 설치해 줘"라고 부탁하세요.)

💡 팁: 이 맥에는 2026-11-20에 Claude Code와 Codex용 herdr 스킬이 이미 설치됐어요. 설치된 버전의 스킬 내용은 herdr --skill로 볼 수 있어요.

고급 1장. AI 팀장 만들기: 메인 1명 + 도우미 N명

회사에서 팀장 한 명이 일을 나눠 주고, 팀원들이 각자 책상에서 일한 뒤 보고하는 모습을 떠올려 보세요. Herdr에서는 칸(페인) 하나하나가 팀원의 책상이에요. 이 장에서는 AI 팀장에게 말 한마디로 AI 팀원을 불러오게 해 봐요.

여기서 쓰는 말을 먼저 정리할게요.

  • 메인 에이전트: 나와 대화하는 팀장 AI예요.
  • 도우미(helper): 메인이 새 칸에 불러낸 팀원 AI예요.
  • 스킬(skill): 에이전트가 읽는 Herdr 사용 설명서예요. 이게 있어야 AI가 칸을 나누고 다른 AI를 띄울 수 있어요.

먼저 알아 둘 원칙 세 가지

  1. 메인은 대화, 구현은 새 칸으로. 메인에게 직접 작업까지 시키면, 그동안 메인은 나와 대화를 못 해요. 실제 작업은 늘 새 칸의 도우미에게 넘겨요(코드팩토리 영상이 가장 강조한 원칙이에요).
  2. 역할과 보고 경로는 사람이 정해요. 에이전트를 여러 개 켜 두기만 하면 알아서 협업하지 않아요. "누가, 무엇을, 어디로 보고할지"를 사람이 알려 줘야 일이 시작돼요(단테랩스 영상).
  3. 승인과 신뢰 확인은 사람 몫이에요. 도우미가 "이 명령 실행해도 될까요?"라고 물으면 메인이 대신 답하면 안 돼요. herdr 스킬 원문도 "승인·질문 화면 앞에서는 대신 답하지 말고 사용자에게 물어보라"고 안내해요.

💡 팁 에이전트를 하나만 쓴다면 이 장은 건너뛰어도 괜찮아요. 김플립 영상도 "프로젝트 하나에 에이전트 하나라면 쓰던 터미널로 충분하다"고 했어요.

준비: herdr 스킬이 있어야 말로 시킬 수 있어요

스킬은 에이전트에게 "Herdr에서 칸을 나누고, 다른 에이전트를 띄우고, 서로 메시지를 보내는 법"을 알려 주는 설명서예요. lustoykov 영상은 이 스킬을 "매우 중요하니 꼭 설치하라"고 강조했어요.

이 맥에는 스킬이 이미 깔려 있어서, 아래 실습을 바로 할 수 있었어요. 새 컴퓨터라면 공식 문서의 설치 예를 쓰면 돼요.

이렇게 입력하세요(공식 문서의 설치 예).

npx skills add herdrdev/herdr --skill herdr -g

지금 쓰는 Herdr 버전에 맞는 스킬 내용은 이렇게 볼 수 있어요.

herdr --skill

단계 1. 통합 상태부터 확인해요

통합(integration)은 에이전트와 Herdr를 잇는 전달선이에요. 화면만 나갔다 들어오는 건 통합과 상관없이 그대로예요. 통합은 서버가 실제로 다시 시작됐을 때 지원되는 AI의 대화를 다시 찾아 여는 데 필요해요(모든 작업의 복구를 보장하지는 않아요). AI 대화창이 아닌, 명령을 기다리는 칸에서 아래 명령으로 확인해요.

이렇게 입력하세요.

herdr integration status
  • outdated: 설치는 됐지만 옛 버전이에요. 업데이트를 권해요.
  • not installed: 설치가 안 됐어요. 그 에이전트를 안 쓰면 그냥 두세요.

이 맥은 2026-11-20 기준으로 Claude·Codex·Hermes 통합이 옛 버전이었어요. 쓰는 것만 하나씩 업데이트하세요.

이렇게 입력하세요.

herdr integration install claude
herdr integration install codex
herdr integration install hermes

✅ 확인하기 다시 herdr integration status를 입력해서 outdated 표시가 사라졌는지 보세요.

단계 2. 메인 Claude에게 말로 부탁해요

Herdr 칸 하나에서 claude를 실행해 메인으로 삼아요(1부에서 해 본 방법 그대로예요). 그리고 아래 문장을 그대로 붙여 넣어요. 연습노트.md는 앞에서 만든 연습 파일이에요. 없다면 가지고 있는 아무 문서 이름으로 바꾸세요.

🗣️ 이렇게 말해 보세요

herdr 스킬을 써서 지금 탭에서 내 칸 아래쪽에 새 칸을 열고, 거기에 Claude 도우미를 helper라는 이름으로 띄워줘. 도우미에게 '연습노트.md를 읽고 한 문장으로 요약해줘'라고 시키고, 끝나면 그 결과를 나에게 알려줘.

💡 팁 문장에 "herdr 스킬을 써서"처럼 herdr를 분명히 넣으세요. 스킬 설명서에 "사용자가 Herdr를 직접 언급할 때 쓰라"고 적혀 있어서, 그래야 확실히 켜져요.

단계 3. AI가 도우미 칸을 만드는 걸 지켜봐요

이번 실습에서는 사람이 아무것도 누르지 않았어요. 메인이 스스로 내 칸 아래에 새 칸을 열고 Claude 도우미를 띄웠고, 왼쪽 agents 목록에도 helper라는 이름이 새로 생겼어요. 다만 환경에 따라 실행 승인이나 폴더 신뢰 질문이 뜰 수 있어요. 그럴 때는 사람이 읽고 답할 때까지 기다려요.

단계 4. 메인이 도우미의 결과를 읽어 오게 해요

도우미가 일을 마치면, 메인이 herdr 명령으로 도우미 칸의 화면을 읽어 와요. 사람이 창을 오가며 복사하고 붙여 넣을 필요가 없어요.

그림에서 메인이 실행한 명령은 아래와 같아요. 사람이 입력할 필요는 없고, 읽기만 하세요.

herdr agent read helper --source recent-unwrapped --lines 60

뜻은 "helper 칸에 최근 나온 글을 60줄 읽어 와"예요.

단계 5. 최종 보고를 읽고, 멈춘 부분은 직접 결정해요

메인이 도우미의 결과를 그대로 전해 주고, herdr로 무슨 일을 했는지도 정리해 줘요. 이번 실습에서는 "한 문장"으로 시켰는데 실제로는 두 문장이 나왔다는 점까지 솔직하게 알려 줬어요.

눈여겨볼 장면이 하나 더 있어요. helper 입력창에 "블로그 폴더도 읽고 요약해줘"라는 문장이 보였어요. 누가 넣었는지 확실하지 않아서, 메인은 "내가 넣은 게 아니라서 실행하지 않았다"며 멈추고 사람에게 물어봤어요(Claude Code가 띄운 추천 문구일 가능성이 크다고 했어요).

이렇게 확인하고 멈추는 습관이 안전한 팀 운영의 기본이에요. 결과가 마음에 안 들면 메인에게 다시 부탁하면 돼요. 그림 아래 입력창의 "helper한테 한 문장으로 다시 요약시켜줘"처럼요.

단계 6. 다 쓴 도우미 칸을 닫아요

일이 끝난 도우미 칸은 닫아도 돼요. 메인에게 "helper 칸을 닫아 줘"라고 말하거나, 1부에서 배운 대로 그 칸을 오른쪽 클릭해서 Close pane을 고르면 돼요.

⚠️ 주의 herdr 스킬은 "자기가 만들지 않은 칸·탭·작업공간은 사용자가 시키지 않으면 닫지 않는다"는 규칙을 따라요. 닫아 달라고 할 때는 칸 이름(helper)을 정확히 말해 주세요.

고급 3장. 워크트리: 원본은 두고 복사본에서 실험하기

중요한 문서를 고칠 때, 원본은 서랍에 두고 복사본을 꺼내 마음껏 고쳐 본 적 있으시죠? 마음에 들면 원본에 옮겨 적고, 아니면 복사본을 버리면 돼요. 워크트리가 바로 그 방법이에요.

워크트리를 쉬운 말로

  • 워크트리(worktree): 원본은 그대로 두고 만든 작업용 사본 폴더예요.
  • Git(깃): 파일이 바뀐 기록을 차곡차곡 남겨 주는 도구예요. 워크트리는 Git으로 관리하는 폴더에서만 만들 수 있어요.
  • 브랜치(branch): 같은 원고의 다른 판본에 붙인 이름이에요. 예: feature/new-idea.
  • 합치기(merge): 사본에서 고친 내용을 원본에 반영하는 거예요.

공식 문서의 설명은 이래요. 워크트리는 하나의 Git 저장소를 함께 쓰면서, 별도 폴더에서 다른 브랜치를 작업하게 해 줘요. Herdr TUI에서 워크트리를 만들면 새 작업공간이 열리고, 원래 작업공간 아래에 묶여서 보여요.

  • 고급 2장처럼 시안 여러 개를 동시에 받을 때

단계 1. 연습 폴더를 Git 폴더로 만들어요

워크트리는 Git 폴더에서만 만들 수 있어요. 이 맥의 실습에서는 먼저 연습 폴더를 Git 폴더로 만들고 첫 기록(커밋)을 남겼어요.

연습 폴더에 비밀이 없는 파일(예: 연습노트.md) 하나가 있는 상태에서, 한 줄씩 입력하세요.

# 1) 지금 위치가 연습 폴더인지 확인
pwd
# 2) 이 폴더를 Git 폴더로 만들기
git init
# 3) 기록할 파일을 하나만 고르기
git add -- 연습노트.md
# 4) 무엇이 기록될지 확인
git status
# 5) 첫 기록 남기기
git commit -m "첫 기록"

pwd 결과가 연습 폴더가 아니면 멈추세요(홈 폴더 같은 곳에서 하면 개인 파일까지 기록될 수 있어요). 오류가 나면 워크트리 만들기로 넘어가지 말고 에이전트에게 오류 문장을 보여 주며 물어보세요. 아래 그림 고-3-1의 맨 위 두 줄은 이 맥에서 같은 일을 한 줄로 실행한 결과예요.

💡 팁 명령이 부담스러우면 에이전트에게 부탁해도 돼요. "이 폴더를 git 저장소로 만들고 첫 커밋을 해 줘. 실행 전에 무엇을 하는지 설명해 줘."

단계 2. Ctrl+B → Shift+G로 새 워크트리를 만들어요

프리픽스 Ctrl+B를 눌렀다 떼고, Shift+G를 눌러요. "new worktree" 창이 떠요. 마우스가 편하면 사이드바의 작업공간을 오른쪽 클릭해서 New worktree를 골라도 돼요(공식 문서 기준).

  • branch 칸: 새 갈래 이름을 적어요. 예: feature/new-idea. 미리 적힌 글자가 있으면 지우고 적어요. 이 맥에서는 Ctrl+C로 한 번에 지워졌고, 공식 문서 기준으로는 Ctrl+U(처음까지 지우기)도 쓸 수 있어요.
  • checkout 칸: 사본 폴더가 생길 위치예요. 자동으로 채워져요. 이 맥에서는 홈 폴더 안 .herdr/worktrees/ 아래였어요.
  • Enter(create and open)를 누르면 만들어지고, Esc(cancel)를 누르면 취소돼요.

단계 3. 사이드바에서 사본 작업공간을 확인해요

원래 작업공간 아래에 └─ feature/new-idea가 매달려 생겨요. 오른쪽의 ▾ 표시로 접고 펼 수 있어요. 새 칸은 사본 폴더(feature-new-idea)에서 열려요.

✅ 확인하기 새 칸의 입력 줄 맨 앞에 feature-new-idea %처럼 사본 폴더 이름이 보이면 성공이에요.

단계 4. 사본에서 에이전트에게 일을 시켜요

사본 작업공간의 칸에서 에이전트를 띄우고 일을 시키면 돼요. 사본에서 고친 내용은 합치기 전까지 원본 파일에 반영되지 않아요. 다만 워크트리는 편집할 폴더를 나눌 뿐, AI가 다른 폴더나 계정에 접근하지 못하게 막아 주지는 않아요.

워크트리 만들기 자체를 말로 시킬 수도 있어요. 코드팩토리 영상의 두 가지 부탁이에요.

🗣️ 이렇게 말해 보세요 (사이드바에 작업공간으로 등록하는 방식)

feature/update 워크트리를 생성하고 워크스페이스에 등록해 줘

🗣️ 이렇게 말해 보세요 (지금 탭에 칸만 추가하는 방식)

feature/test 워크트리를 만들고 현재 탭 오른쪽에 codex로 칸을 만들어 줘

영상 원문에는 codex --yolo(승인 없이 실행하는 모드)가 들어 있었어요. 초보자는 빼고 쓰세요.

지금 탭에 칸으로만 추가 여러 사본을 한눈에 같이 보고 싶을 때 사이드바엔 안 생기고 지금 탭에 칸만 늘어요

단계 5. 합치거나 버리는 건 말로 부탁해요

실험이 끝나면 둘 중 하나를 골라요. 마음에 들면 원본에 합치고, 아니면 사본을 버려요.

Git 명령을 몰라도 괜찮아요. 에이전트에게 말로 부탁하는 게 가장 쉬워요.

🗣️ 이렇게 말해 보세요 (합칠 때)

feature/new-idea 워크트리에서 바뀐 내용과, 두 폴더의 경로·브랜치 이름, 아직 기록하지 않은 변경을 먼저 보여줘.
내가 고른 변경만 기록하고, 내가 확인한 원본 브랜치에 합쳐줘. 충돌하면 멈추고 알려줘.

🗣️ 이렇게 말해 보세요 (버릴 때)

feature/new-idea 워크트리를 정리하고 싶어. 지우면 무엇이 사라지는지 먼저 알려주고, 내가 좋다고 하면 지워줘.

마우스로 할 수도 있어요. 사본 작업공간을 오른쪽 클릭하면 Delete worktree checkout...(사본 폴더 삭제)이 있어요. 원래 작업공간의 오른쪽 클릭 메뉴에는 이미 있는 사본을 다시 여는 Open worktree...도 있어요(공식 문서 기준).

⚠️ 주의 "작업공간 닫기"와 "사본 폴더 삭제(Delete worktree checkout)"는 서로 다른 일이에요. 공식 문서도 둘을 꼭 구분하라고 해요. 누르기 전에 메뉴 이름을 한 번 더 확인하세요.

워크트리 안전 수칙

⚠️ 주의

  • --trust-repository처럼 "이 저장소를 믿는다"고 표시하는 옵션은, 사람이 저장소를 확인한 뒤에만 써요(herdr 스킬 원문의 규칙).
  • codex --yolo, bypass permissions는 승인 절차를 끄는 모드예요. 워크트리 안이라도 AI가 닿을 수 있는 범위가 좁아지는 건 아니니, 이 책의 실습에서는 켜지 마세요.
  • "이 폴더를 믿을까요?(Trust this folder?)" 질문에는, 그 신뢰가 적용될 원래 저장소 경로까지 읽어 본 뒤 직접 답해요. 그림 고-3-3 오른쪽에도 "신뢰는 저장소 맨 위 폴더에 적용된다"는 문구가 있어요.
  • 워크트리를 10~20개씩 만들면 디스크 공간을 많이 차지해요(lustoykov 영상). 다 쓴 사본은 정리하세요.
  • 여러 AI가 사본 없이 한 폴더에서 동시에 일하게 하는 방식도 영상에 나와요. 하지만 서로 덮어쓸 위험이 큰 고급 방식이라 초보자에게는 권하지 않아요.

고급 4장. 다른 컴퓨터를 한 화면에 (TUI 원격)

집에는 맥북, 사무실에는 맥 미니가 있다고 해 볼게요. Herdr는 두 컴퓨터의 에이전트를 맥북 화면 하나에 모아 보여 줄 수 있어요. 일은 각자의 컴퓨터에서 돌아가요.

코드팩토리 영상은 이 기능을 "가장 강력한 기능"으로 꼽았어요. 이 장은 터미널판 Herdr(TUI) 기준이에요. 데스크톱 앱에서 하는 방법은 고급 5장 끝부분에서 다뤄요.

이렇게 연결돼요

  • SSH(다른 컴퓨터에 안전하게 접속하는 통로)로 연결해요.
  • 원격 컴퓨터의 에이전트는 그 컴퓨터의 Herdr 서버에서 돌아가요. 그래서 파일과 계산 능력도 그 컴퓨터 것을 써요.
  • 컴퓨터마다 서버와 세션이 따로라서, 한 대가 끊겨도 다른 컴퓨터는 영향을 받지 않아요(공식 문서).
  • 이 맥의 버전(0.9.5)과 같은 버전의 공식 문서에 실린 기능이에요.

단계 1. 평범한 SSH 접속부터 확인해요

Herdr보다 SSH가 먼저예요. 내 컴퓨터의 터미널에서 원격 컴퓨터에 접속되는지 확인해요.

이렇게 입력하세요(mac-mini 자리에 내 SSH 별칭을 넣어요).

원격 컴퓨터의 입력 줄이 보이면 성공이에요. exit를 입력하면 내 컴퓨터로 돌아와요.

단계 6. Tailscale로 밖에서도 연결해요

같은 Wi-Fi가 아닐 때(예: 카페에서 사무실 맥 미니에 접속)는 Tailscale을 써요. Tailscale은 내 기기끼리만 통하는 개인 네트워크를 만들어 주는 앱이에요(무료로 시작할 수 있는 VPN).

  1. 모든 컴퓨터에 Tailscale을 설치하고, 같은 계정으로 로그인해요.
  2. 켜 두면 멀리 떨어져 있어도 같은 네트워크처럼 인식돼요.
  3. 그다음 단계 1부터 똑같이 해요. Tailscale이 붙여 준 주소(100으로 시작하는 주소)나 기기 이름으로 SSH 접속하면 돼요.

다른 방법도 있어요

표시 뜻 이렇게 해 보세요

! error 연결 오류 herdr machine status 이름 --json으로 원인 보기, 안내되는 herdr --remote 대상 실행
회색 상태 마지막으로 받은 정보예요(실시간 아님) 연결이 돌아오길 기다리거나 reconnect

💡 팁 herdr machine reconnect는 지원되는 플랫폼에서만 되고, 설치나 업데이트는 하지 않아요(공식 문서).

연결을 그만두고 싶을 때는 herdr machine disable 프로필ID(끄기)나 herdr machine remove 프로필ID(목록에서 빼기)를 써요. 둘 다 접속만 끊고, 원격에서 돌던 작업은 그대로 둬요.

고급 5장. Herdr 데스크톱 앱(Herdr.app) 시작하기

지금까지는 터미널 안에서 쓰는 Herdr(TUI)를 배웠어요. Herdr에는 창으로 된 데스크톱 앱도 있어요. 마우스로 쓰기 편하고, 화면 모양을 말로 바꿀 수 있고, 공식 휴대폰 앱과도 이어져요.

먼저 꼭 알아 둘 것: TUI와 다른 제품이에요

이름은 같지만 서로 다른 프로그램이에요. 공식 FAQ는 "Herdr TUI는 자체 서버를 가진 원래의 터미널 앱이고, 데스크톱은 herdr-core 위에 새로 만든 별도 프로그램이라 에이전트를 공유하지 않는다"고 설명해요.

그림 고-5-1. 공식 FAQ "How is it different from Herdr TUI?": 두 프로그램은 에이전트를 공유하지 않아서, 한쪽에서 돌리는 것이 다른 쪽에 보이지 않는다는 설명

영상 속 유튜버가 함께 보이는 화면이라 공개판에서는 그림을 뺐어요. ▶ 단테랩스 「Herdr 데스크톱으로 멀티 에이전트 오케스트레이션」 12:20 장면 보기

그러니까 TUI에서 돌리던 에이전트는 데스크톱 앱이나 공식 휴대폰 앱에 나타나지 않아요. 같은 프로젝트 폴더는 양쪽에서 다 쓸 수 있어요.

구분 Herdr TUI (1~4장) Herdr 데스크톱 앱 (이 장)

여기부터는 Collie가 이미 설정된 사람을 위한 영상 예예요. 처음이라면 공식 앱(①)이나 SSH 앱(③)을 먼저 쓰세요. Collie를 쓸 때는 본인이 확인한 비공개 접속 주소에서만 연결하고, 연결 코드와 기기 등록용 QR은 다른 사람에게 보내거나 대화창에 붙이지 마세요. 단테랩스 영상의 순서는 이래요.

  1. 컴퓨터와 아이폰에 Tailscale을 깔고, 같은 계정으로 로그인해요.
  2. 컴퓨터에서 Collie를 실행할 때 연결 대상을 herdr-core로 지정해요.
  3. 아이폰 브라우저로 Collie 주소에 접속해요. 홈 화면에 추가하면 앱처럼 쓸 수 있어요.
  4. Collie의 설정 → System에서, 컴퓨터에서 collie pair로 받은 연결 코드를 넣고 기기 이름을 붙여요.

고급 7장. 안전하게 오래 쓰기

Herdr를 오래, 안심하고 쓰려면 몇 가지 습관이 필요해요. 이 장은 실습보다 규칙 위주예요. 한 번 읽어 두고, 가끔 다시 펼쳐 보세요.

규칙 1. 업데이트는 일을 정리한 뒤, Herdr 밖에서 해요

herdr update는 Herdr 서버를 다시 시작하게 될 수 있어요. 그러면 Herdr 안에서 돌던 작업이 끊길 수 있어요. 그래서 에이전트 작업을 먼저 정리하고, Herdr 밖의 일반 터미널 창에서 업데이트하세요.

먼저 어떻게 설치했는지 확인해요. Herdr 설치 스크립트(install.sh)로 깔았을 때만 herdr update를 써요. Homebrew·mise·Nix로 깔았다면 그 도구로 업데이트하고, 방식이 분명하지 않으면 버전만 확인하고 멈춰요.

이렇게 입력하세요(Herdr 밖의 터미널에서).

herdr --version
herdr update
  • Herdr 칸 안에서 herdr를 다시 실행하는 것은 막혀 있어요(중첩 실행 방지). 업데이트와 재접속은 늘 바깥 터미널에서 해요.
  • Homebrew로 설치했다면 Homebrew로 업데이트해요. Herdr의 업데이트 채널 기능은 쓰지 않아요.
  • 실행 중인 서버가 옛 버전 같으면 herdr status로 화면(클라이언트)과 서버의 버전을 따로 확인해요.
  • herdr channel show로 지금 채널을 볼 수 있어요. 초보자는 기본인 stable(안정판)을 그대로 쓰세요. preview는 개발 중인 미리보기판이에요.
  • herdr update --handoff라는 실험 기능도 있지만, 진행 중인 요청이 끊길 수 있어서 초보자에게는 권하지 않아요.
  • 데스크톱 앱의 엔진은 hc update로 업데이트해요. 공식 안내로는 돌던 터미널이 유지돼요.

💡 팁 1.0 전이라 Herdr는 자주 바뀌어요. 단축키가 갑자기 안 먹으면 업데이트부터 확인해 보세요(윤자동 영상의 조언). 업데이트한 뒤에는 고급 1장의 herdr integration status도 다시 확인하세요.

규칙 3. 승인과 막힘(blocked)은 사람이 판단해요

  • 상태 표시는 100% 정확하지 않아요. Herdr는 화면 글자를 보고 판단해서, 처음 보는 질문 화면은 idle(쉬는 중)로 잘못 보일 수 있어요.
  • 그러니 idle을 "허락받았다"는 뜻으로 받아들이면 안 돼요. 오래 조용하면 그 칸을 직접 열어 보세요.
  • 이상하면 herdr agent explain 이름 --json으로 Herdr가 왜 그 상태로 판단했는지 볼 수 있어요.
  • 승인할 때는 질문을 끝까지 읽어요. 그림처럼 1. Allow(이번만 허락)가 Always allow(늘 허락)보다 안전해요.

규칙 4. 승인 건너뛰기 모드(yolo, bypass)는 조심해요

  • codex --yolo, Claude의 bypass permissions는 승인 절차를 끄는 모드예요. 영상 데모에 자주 나오지만, 그대로 따라 하지 마세요.
  • 워크트리나 연습 폴더 안이라도 AI의 접근 범위가 좁아지지는 않아요. 초보자는 켜지 않는 게 원칙이에요. 중요한 계정이 연결된 곳이나 남의 저장소에서는 절대 쓰지 마세요.
  • 이 모드에서는 에이전트가 묻지 않고 바로 실행해요. "막힘 알림을 보고 사람이 판단한다"는 Herdr의 장점도 함께 사라져요.

규칙 5. 플러그인·모드·레이아웃은 "실행되는 코드"예요

  • TUI 플러그인 마켓에는 "목록은 Herdr가 검토하지 않으니 본인 판단으로 설치하라"는 문구가 있어요.
  • 플러그인은 내 계정 권한으로 명령을 실행하고, 따로 격리되지 않아요(공식 문서).
  • 설치 미리보기(Plugin install preview)에서 출처, 실행할 명령, 외부 통신을 확인하고, 내가 허용하려는 범위와 맞을 때만 y를 눌러요. 모르겠거나 예상과 다르면 취소해요. 미리보기가 코드 검토를 대신해 주지는 않아요.
  • 데스크톱 앱의 레이아웃과 모드도 JavaScript 코드예요. 에이전트에게 먼저 읽고 설명하게 하세요.

규칙 6. 포트를 인터넷에 열지 않아요

  • 포트(port)는 컴퓨터가 바깥과 주고받는 문의 번호예요.
  • Ovis(127.0.0.1:7317) 같은 웹앱의 포트를 인터넷에 그대로 열면 안 돼요. 공유기 포트 전달이나 인터넷 공개 기능도 켜지 마세요.
  • 밖에서 쓰려면 Tailscale 같은 개인 네트워크를 써요. 단, tailscale serve는 "내 기기만"이 아니라 "내 Tailscale 네트워크 전체"에 여는 거예요. 네트워크를 함께 쓰는 사람이 있으면 접근 권한을 먼저 확인하세요.
  • Herdr의 소켓 API(프로그램이 Herdr를 조작하는 통로)는 공개 웹 API가 아니라 권한 있는 조작 통로예요(공식 문서). 바깥에 열지 마세요.

규칙 7. 비밀번호와 비밀 정보는 프롬프트에 쓰지 않아요

  • 에이전트에게 보내는 글에 비밀번호, 인증 코드, 토큰을 적지 마세요. 화면과 대화 기록에 그대로 남아요.
  • 비밀번호가 필요한 곳(SSH 로그인, 공식 모바일 앱의 Sign in 칸)에는 내가 직접 입력해요. 공식 모바일 앱은 그 비밀번호를 한 번만 쓰고 저장하지 않는다고 안내해요.
  • 화면 기록 저장 옵션([experimental]의 pane_history = true)은 기본으로 꺼져 있어요. 켜면 토큰·프롬프트·비밀이 파일에 남을 수 있어요.
  • 문제를 물어보려고 로그 파일을 공유할 때는 비밀과 개인정보를 먼저 지우세요.

B-2. herdr 스킬로 화면 다루기 (herdr 칸 안의 AI에게)

herdr로 지금 탭 오른쪽에 새 칸을 열고 codex를 띄워 줘.

herdr로 내 칸 아래쪽에 새 칸을 열고 Claude 도우미를 helper라는 이름으로 띄워 줘. 도우미에게 "○○를 읽고 한 문장으로 요약해 줘"라고 시키고, 끝나면 그 결과를 나에게 알려 줘.

herdr로 지금 이 작업공간에 있는 에이전트들의 상태를 표로 정리해 줘. 막혀 있는(blocked) 에이전트가 있으면 무엇을 묻고 있는지도 알려 줘. 승인은 내가 직접 할게.

B-3. 팀으로 일 시키기 (고급 1~2장)

- 도우미 1 (codex, 이름 builder): ○○를 만든다
- 도우미 2 (claude, 이름 reviewer): builder 결과를 읽기 전용으로 검토한다
각 도우미에게는 끝나면 결과를 너에게 보고하라고 알려 줘. 도우미가 승인을 기다리면 대신 답하지 말고 나에게 먼저 물어봐.

herdr로 현재 탭에 칸 3개를 만들어 각각 다른 콘셉트로 ○○ 시안을 동시에 만들어 줘. 각자 다른 폴더(또는 워크트리)에서 작업하게 하고, 다 끝나면 세 시안을 비교표로 정리해 줘.

B-4. 데스크톱 앱 꾸미기 (공식 Guide 예시, 번역)

부록 C. 문제 해결 (자주 막히는 곳)

증상 해결
command not found: herdr 터미널을 완전히 닫고 새로 열기. 그래도 안 되면 설치 명령을 다시 실행하거나 AI에게 "PATH에 herdr 설치 폴더가 있는지 확인해 줘"
Ctrl + B 다음 글자가 안 먹어요 먼저 영어 입력으로 바꿔 다시 눌러요. 맥·윈도우는 실험 설정 switch_ascii_input_source_in_prefix = true(중급 5장)를 써 볼 수 있어요. herdr --version으로 버전을 보고 0.9.5보다 낮으면 작업을 정리한 뒤 업데이트해요(herdr update는 실제 업데이트라 서버가 다시 시작될 수 있어요. 고급 7장 참고). Homebrew로 깔았다면 Homebrew로 업데이트해요
한글 조합창이 엉뚱한 곳에 떠요 설정 reveal_hidden_cursor_for_cjk_ime = true (맥). 윈도우는 [ui] 아래 host_cursor = "native"
AI가 사이드바에 안 잡혀요 herdr 칸 안에서 직접 실행했는지 확인. herdr integration status로 통합 점검, herdr agent list로 인식 목록 확인
상태가 이상해요 (질문 중인데 ○로 보임) 상태 표시는 화면 글자로 짐작해서 100% 정확하지 않아요. 오래 조용한 칸은 직접 들어가 보기. 통합 최신화
껐다 켰는데 대화가 안 이어져요 통합 설치 여부 확인(herdr integration status). 재부팅·서버 중지 후에는 돌던 작업은 사라지고 대화만 다시 열 수 있어요
Ctrl + C를 눌렀더니 AI가 멈췄어요 터미널에서 Ctrl+C는 "멈춤"이에요. 복사는 마우스 드래그 또는 ⌘+C
맥에서 Option+← 가 ;3D로 찍혀요 터미널 앱 설정에서 Option을 Meta(Alt)로 쓰기 켜기
Enter·Backspace가 두 번 입력돼요 오래된 터미널 앱에서 생기는 문제예요. 쓰던 터미널 앱이 최신인지 확인하거나 Ghostty를 써 봐요
화면이 깨져 보여요 다른 창을 클릭했다가 터미널로 돌아오면 herdr가 화면을 새로 그려요(기본 설정 redraw_on_focus_gained). 그래도 이상하면 Ctrl + B → q로 나갔다가 herdr로 다시 들어오기
원격 머신에 ! auth 표시 일반 ssh 이름 접속부터 확인. 키 암호가 있으면 ssh-add. 그다음 herdr machine reconnect 이름
플러그인이 안 열려요 herdr config check로 설정 오류 확인 → herdr server reload-config. 단축키 블록을 붙였는지 확인
(데스크톱 앱, 윈도우) Codex가 "Access is denied" Codex 데스크톱 앱과 충돌. codex --no-daemon으로 실행 (출처: 영상 Techalyzing)
(데스크톱 앱) Changes 패널이 "Not a git repository" 지금 연 폴더가 Git(변경 이력 관리)을 쓰는 프로젝트가 아니라는 뜻이에요. 기존 프로젝트라면 그 폴더를 다시 열고, Git을 안 쓰면 Changes 패널은 건너뛰어요. 새 연습 프로젝트로 쓰기로 한 폴더에서만 git init을 해요 (출처: 영상 Techalyzing)
(데스크톱 앱) 화면을 꾸미다 망가졌어요 Ctrl + Alt + Shift + Esc로 기본 화면(main)으로 복구 (출처: 공식 AGENTS.md)

부록 G. 이 책의 근거와 한계

근거 수준 해당 내용
실제 실행 (이 맥, herdr 0.9.5) 초급의 화면 조작과 상태 확인, 중급 1~4장, 고급 1장 실습, 고급 3장 워크트리 생성. 연습용 이름 있는 세션을 따로 만들어 기존 작업과 섞이지 않게 실행했고, 끝난 뒤 세션·연습 폴더·워크트리를 지웠어요. 설치 명령은 입력 예시까지만 찍었고(이미 설치된 맥), 설치 완료 화면은 영상에서 인용했어요. 윈도우 설치와 이 맥의 통합 업데이트는 직접 하지 않았어요
영상 화면·자막 중급 5장 config 예시, 중급 6장 플러그인 설치, 고급 2·4·5·6장 (데스크톱 앱, 원격 머신, 휴대폰)
공식 문서 단축키 전체, 설정 이름, 통합 목록, 세션 유지 규칙, 문제 해결

한계

  • 데스크톱 앱, 공식 모바일 앱, 원격 머신 연결, 플러그인 설치는 이 맥에서 직접 실행하지 않았어요. 영상과 공식 문서 기준이며, 특히 데스크톱 앱(0.1.x)은 몇 주 사이에도 화면과 문구가 바뀌고 있어요.
  • 실제 화면의 Claude·Codex 답변 말투, 상태줄, MCP 안내는 이 맥의 개인 설정이에요.
  • 영상 자막은 대부분 자동 생성이라 고유명사가 틀린 곳(허더, 티웍스 등)을 화면과 문서로 바로잡았어요.
  • 명령이 안 맞으면 herdr --help, Ctrl + B → ?, herdr --skill이 언제나 가장 최신 기준이에요.
